# Getting help with Nautelle

| You want to | Go to |
|---|---|
| Install or run Nautelle | [Installing Nautelle](docs/guides/install.md), the wiki's [Getting started](https://github.com/AndreyBegma/Nautelle/wiki/Getting-Started) and [Self-hosting](https://github.com/AndreyBegma/Nautelle/wiki/Self-Hosting) |
| Pair or update a runner | [Installing the runner](https://github.com/AndreyBegma/Nautelle/wiki/Installing-the-Runner) and [`apps/runner/README.md`](apps/runner/README.md) |
| Understand a feature | The [wiki](https://github.com/AndreyBegma/Nautelle/wiki) |
| Understand why it is built this way | [`docs/`](docs/README.md): ADRs, architecture, specs |
| Ask a question or share an idea | [Discussions](https://github.com/AndreyBegma/Nautelle/discussions) |
| Report a bug | A [bug report](https://github.com/AndreyBegma/Nautelle/issues/new?template=bug_report.yml) |
| Propose a feature | A [feature request](https://github.com/AndreyBegma/Nautelle/issues/new?template=feature_request.yml) |
| Report a vulnerability | **Not in public.** See [`SECURITY.md`](SECURITY.md) |
| Contribute code | [`CONTRIBUTING.md`](CONTRIBUTING.md) |

Before you open an issue, search the existing ones and check that you run the
latest release. A good bug report names the Nautelle version, the runner
version and the operating system, and says what you did, what you expected and
what happened.

Nautelle is maintained by a small team in the open. There is no guaranteed
response time for questions and bug reports; security reports have their own
targets in [`SECURITY.md`](SECURITY.md).
