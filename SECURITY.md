# Security Policy

## Supported Versions

Security updates are provided for the latest stable release.

| Version | Supported |
| ------- | --------- |
| Latest stable release | :white_check_mark: |
| Older releases | :x: |

We recommend always using the latest stable version to ensure you receive
the latest security fixes.

## Reporting a Vulnerability

If you discover a security vulnerability in AgentDock, please report it
responsibly.

**Please do not disclose security vulnerabilities through public GitHub
issues or discussions.**

### How to Report

Use [GitHub Private Vulnerability Reporting](https://github.com/AndreyBegma/AgentDock/security/advisories/new)
to submit a vulnerability report privately.

Please include as much information as possible:

- A description of the vulnerability.
- Steps to reproduce the issue.
- The potential impact.
- Any proof of concept or relevant logs, if available.
- Suggested mitigations or fixes, if known.

### Response Timeline

- **Initial response:** Within 7 days.
- **Status updates:** As significant progress is made.
- **Resolution:** Depends on the severity and complexity of the vulnerability.

We will investigate each report and work toward a fix as appropriate.

### What to Expect

- **If accepted:** We will assess the impact, develop a fix, and coordinate
  disclosure when appropriate.
- **If declined:** We will explain why the report does not qualify as a
  security vulnerability, to the extent possible.

We ask reporters to give us reasonable time to investigate and address
reported vulnerabilities before making them public.

### Scope

This policy applies to the AgentDock project and its officially maintained
components.

Thank you for helping keep AgentDock and its users secure.
