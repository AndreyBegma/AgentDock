Runner tokens: security review

Tokens are minted once at registration, stored as a SHA-256 hash and checked by a guard on every runner request. The model is sound. Three things are worth fixing, ordered by risk:

  1. High
    Hash compared with ===

    The guard compares the stored hash with a plain string equality. Use a constant-time comparison so response timing does not leak the prefix.

  2. Medium
    Tokens never expire or rotate

    A leaked token is valid until someone deletes the runner. Add rotation and a last-used timestamp shown on the runner page.

  3. Low
    No rate limit on failed runner auth

    Failed attempts are not throttled per IP, unlike password checks (C-109).

Issuance and storage look right: the plaintext token is shown once and never logged.
