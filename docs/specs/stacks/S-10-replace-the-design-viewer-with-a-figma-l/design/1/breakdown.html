What changes

1

Frame tabs

Changed
glass-ui/tabs · TabList, Tab, Badge

Behaviour. One tab per frame of the revision, in template order. The open-comment count is shown as a badge, and the tab lives in ?frame=. ←/→ move between tabs.

Why. Replaces the frame strip; a frame is now a whole canvas, not one picture.

2

Device canvas

New
glass-ui · ZoomCanvas (new, C-345)

Behaviour. Drag or scroll pans. ⌘/Ctrl + scroll and pinch zoom around the pointer, from 8% to 400%. The dot grid moves with the pan so motion reads.

Why. Comparing three widths side by side beats toggling one viewport.

3

Device frame

New
sandboxed iframe per device · icon + name + size label

Behaviour. The frame's one HTML is rendered at each device's width × height, in the order the devices were chosen. The label stays 12px at any zoom. Double-clicking a label zooms to that device.

Why. A single responsive HTML, many widths — the phone is a device, not a frame.

4

Canvas tools

Changed
glass-ui/segmented-control · KeyHint

Behaviour. Move (V) pans. In Comment mode (C), a click pins on the device under the pointer and opens the pin composer. Esc returns to Move.

Why. Dragging to pan and clicking to pin are the same gesture; a mode keeps them apart.

5

Zoom controls

New
glass-ui/button ghost · glass group

Behaviour. − / % / + step by 25%. Fit frames every device and is the default on open. 100% shows true pixels. ⌘0 fits, ⌘1 sets 100%.

Why. A visible reset for people who do not know the gestures.

6

Pins on devices

Changed
pin · frame + device + x/y in device pixels

Behaviour. A pin is anchored to a device's own coordinates, so it moves and scales with the canvas while its marker keeps a fixed size. The selected pin rings, and its device gets an accent outline.

Why. "The tablet header" is a different comment from "the desktop header".

7

Comments

Changed
comments-panel · Open / All segmented

Behaviour. Each comment shows its frame and device. Selecting a comment switches to its tab and pans to its pin, at 50% zoom or more. Resolved comments sit under All.

Why. Revise reads these comments, so the agent knows which width each note is about.

8

Review toolbar

Removed switch
segmented-control · select × 2

Behaviour. Only theme, variant and revision are left. The Mobile/Desktop viewport switch is removed, and the typed width is gone with it.

Why. The devices on the canvas replace both.

9

Devices of the revision

New
page-header meta · stored on the design (C-344)

Behaviour. Lists the devices this revision was drawn for. They are chosen in the generate panel's Devices group (C-347, see States). Earlier revisions show "as drawn".

Why. The reviewer needs to know which widths were asked for, not only which are shown.
